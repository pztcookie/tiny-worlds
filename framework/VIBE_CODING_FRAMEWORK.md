# 1-Hour Vibe Coding Product Framework

> Build one tiny world with one delightful interaction — not a complete product.

## Core Principle

Don't build a product. Build a behavior.

The core loop:

Action → Surprise → Curiosity → Action

My personal layer:

Action → Surprise → Curiosity → Reflection → “This feels like mine.”

---

## 1. PERSONAL LENS — Why this idea?

Start with:

> What do I uniquely notice about this topic?

Choose ONE personal lens.

Examples:
- Environment shapes identity
- Memory lives inside ordinary objects
- People don't always know what they feel
- Interpretation is never completely objective
- We adapt to environments, but we can also reshape them
- Familiar things can become strange
- People leave traces without realizing it
- Identity emerges through interaction

Rule:

> One lens only. Don't try to put my entire worldview into one demo.

---

## 2. HOOK — Make me stop

Ask:

> What's slightly strange?

Create one small anomaly that makes the user think:

> “Wait… what just happened?”

Examples:
- A bird imitates the user, but not quite correctly
- An object in a photo suddenly moves
- A room seems to remember the user's previous visit
- A creature reacts differently each time
- AI gives an interpretation that feels almost right, but not quite

Goal:

> Create a “What just happened?” moment.

---

## 3. WORLD — Build only enough world

Create:

- 1 world
- 1 character / object
- 1 emotional premise
- 1 visual language

Example:

World: A room that remembers you
Character: A bird
Premise: The bird is learning the user
Visual language: Dreamy pixel apartment

Rule:

> One room in a universe, not an entire universe.

---

## 4. QUEST — Give me a reason to play

Ask:

> What does the user want right now?

Examples:
- Make the bird trust you
- Find what the room is hiding
- Make this place feel like home
- Discover what the photo remembers
- Teach the creature something
- Find the thing that doesn't belong

Principle:

> Goal visible, solution hidden.

The user should understand what they are trying to achieve, but not exactly how the world will respond.

---

## 5. PLAY LOOP — The core interaction

The most important part:

> Action → Response → Notice → Adapt → Try again

Example:

User moves bird
→ bird behaves unexpectedly
→ user notices a pattern
→ user tries something else
→ world responds differently
→ user wants to try again

Interaction principles:

- Easy to start
- Every action creates a consequence
- 3–5 core actions maximum
- Interaction should feel like interacting with a world, not operating a UI

---

## 6. MYSTERY — Give me a reason to play again

Ask:

> What does the user NOT know yet?

Choose ONE mystery.

Examples:
- Why does the bird keep following one object?
- Why does the room become darker?
- Why does one object disappear?
- Why does the game sometimes change its own rule?
- Why does AI interpret the same thing differently?

Goal:

> “I want to try that again.”

Principle:

> One good secret is better than five unfinished mechanics.

---

## 7. PERSONALITY — Let the world have its own will

The world should not simply obey the user.

Use:

> Predictable + Unpredictable

The system should be:

- Responsive
- Partially predictable
- Slightly surprising
- Influencable
- Not completely controllable

The goal is not randomness.

It is:

> Intentional unpredictability.

The user should feel:

> “I haven't completely figured out this world yet.”

---

## 8. TRACE — Let the world remember me

Record a small number of user behaviors.

Use 3–5 state variables maximum.

Examples:
- favoriteObject
- interactionStyle
- repeatedChoice
- explorationLevel
- secretDiscovered

Then let the world react to those behaviors.

Example:

User repeatedly interacts with the window
→ the room eventually creates another window.

User keeps feeding the bird
→ the bird starts following them.

Principle:

> The world should remember that the user was here.

---

## 9. REFLECTION — Don't diagnose. Reflect.

Don't tell the user:

> “You are nostalgic.”

Instead, show what they actually did.

Examples:

> “You came back to the same window 6 times.”

> “You kept choosing things you already knew.”

> “You never opened the red door.”

Then:

> “I wonder why.”

The reflection should feel:

- discovered
- subtle
- personal
- open to interpretation

Principle:

> The reflection should feel discovered, not diagnosed.

---

## 10. TRANSFORMATION — My action mattered

Something should be different because the user was there.

Before:
- Empty room

After:
- My room

Before:
- Unknown creature

After:
- My creature

Before:
- Ordinary photo

After:
- My emotional artifact

Core feeling:

> “I didn't just use this world. I left something inside it.”

---

## 11. TAKE HOME — Give me something

End with something the user can keep or share:

- Creature
- Image
- Room
- Badge
- Artifact
- Poem
- Screenshot
- Personalized world

Goal:

> “I made this.”

or:

> “This feels strangely like me.”

---

# HARD CONSTRAINTS

For a 1-hour prototype:

- 1 WORLD
- 1 GOAL
- 1 CORE MECHANIC
- 1 SECRET
- 3–5 STATE VARIABLES
- 1 TRANSFORMATION
- 1 TAKE-HOME ARTIFACT

Avoid:

- Multiple game mechanics
- Complex navigation
- Large amounts of content
- Too many AI features
- Over-designed UI
- Building a complete product

Focus on:

> One interaction that is surprisingly fun.

---

# MY CREATIVE NORTH STAR

Don't ask:

> “What product should I build?”

Ask:

> “What behavior do I want to create?”

Then:

> What makes the user stop?

> What makes them curious?

> What makes them try something?

> How does the world respond?

> What makes them want to try again?

> What does the world remember about them?

> What can they discover about themselves?

> What changed because they were here?

## Product test

This framework ships no checklist of its own, so a game built from it is still finished by the
ten questions at the end of `PRODUCT_FRAMEWORK.md`, plus one final read: does the session run
Action → Surprise → Curiosity → Reflection → “This feels like mine.”
